# Vibe Kanban 部署须知

## 项目架构

| 组件 | 说明 | 端口 |
|------|------|------|
| 本地前端 (Vite) | React SPA，浏览器直接访问 | 3000 |
| 本地后端 (Rust) | 处理本地仓库/工作区 | 3001 |
| 远程服务器 (Rust) | 登录、项目、Issue、Electric 代理 | 8080 |
| PostgreSQL | 数据库 | 5433（宿主机） |
| ElectricSQL | 实时同步 | 3099（宿主机） |

核心概念：**远程服务器负责登录、项目、Issue；本地 App 负责仓库操作和工作区执行。** 两者配合使用才能获得完整体验。

---

## 一、前置条件

- Node.js 20+、pnpm
- Rust nightly（见 `rust-toolchain.toml`）
- Docker Desktop（仅 PostgreSQL + ElectricSQL 需要）
- GitHub OAuth App（或自托管本地账号）

## 二、启动步骤

### 2.1 配置环境变量

项目根目录 `.env.remote`：

```env
# 必填
VIBEKANBAN_REMOTE_JWT_SECRET=<openssl rand -base64 48 生成>
ELECTRIC_ROLE_PASSWORD=<随机密码>

# GitHub OAuth
GITHUB_OAUTH_CLIENT_ID=<Client ID>
GITHUB_OAUTH_CLIENT_SECRET=<Client Secret>

# 或自托管本地账号
SELF_HOST_LOCAL_AUTH_EMAIL=admin@example.com
SELF_HOST_LOCAL_AUTH_PASSWORD=<密码>
```

### 2.2 构建远程服务器（本地 ARM 原生编译）

Docker 内 x86_64 QEMU 模拟极慢，改为本地编译：

```bash
# 去掉 billing 私有依赖（不需要）
sed -i '' '/^billing = {.*vibe-kanban-private.*/d' crates/remote/Cargo.toml
sed -i '' 's/^vk-billing = \["dep:billing"\]/vk-billing = []/' crates/remote/Cargo.toml

# ARM 原生编译（约 2-3 分钟，极快）
CARGO_NET_GIT_FETCH_WITH_CLI=true cargo build --release \
  --manifest-path crates/remote/Cargo.toml

# 构建前端 SPA
pnpm run remote:generate-types
cd packages/remote-web && pnpm run build && cd ../..
```

### 2.3 启动 PostgreSQL + ElectricSQL（Docker）

```bash
cd crates/remote
docker compose --env-file .env.remote up -d remote-db electric
```

### 2.4 启动远程服务器（原生）

```bash
set -a; source .env.remote; set +a
export SERVER_DATABASE_URL="postgres://remote:remote@localhost:5433/remote"
export ELECTRIC_URL="http://localhost:3099"
export SERVER_LISTEN_ADDR="0.0.0.0:8080"
export SERVER_PUBLIC_BASE_URL="http://localhost:8080"
export ELECTRIC_ROLE_PASSWORD="${ELECTRIC_ROLE_PASSWORD:-remote}"
export RUST_LOG="info,remote=info"

./crates/remote/target/release/remote
```

### 2.5 启动本地 App

```bash
PORT=3000 VK_SHARED_API_BASE=http://localhost:8080 pnpm run dev
```

浏览器打开 `http://localhost:3000/`，用 GitHub 登录即可使用。

## 三、架构说明

### 请求链路

```
浏览器 (localhost:3000)
  ├── /api/*          → Vite 代理 → 本地后端 (3001)
  ├── /v1/*           → Vite 代理 → 远程服务器 (8080)
  └── /v1/shape/*     → Vite 代理 → 远程服务器 (8080) → ElectricSQL (3099)
```

关键设计：**Electric shape 请求走 Vite 代理同源转发，避免跨域问题。**

### Vite 代理配置

```ts
// packages/local-web/vite.config.ts
proxy: {
  '/api': {
    target: 'http://localhost:3001',  // 本地后端
    changeOrigin: true, ws: true,
  },
  '/v1': {
    target: process.env.VITE_VK_SHARED_API_BASE || 'http://localhost:8080',
    changeOrigin: true,
  },
}
```

### 各组件职责

| 功能 | 处理方 |
|------|--------|
| 登录 / OAuth | 远程服务器 (8080) |
| 项目管理 / 看板 | 远程服务器 (8080) |
| Issue CRUD | 远程服务器 (8080) |
| Electric 实时同步 | 远程服务器 → ElectricSQL |
| 选择本地仓库路径 | 本地后端 (3001) |
| 创建 / 管理工作区 | 本地后端 (3001) |
| 代码执行 | 本地后端 (3001) |

## 四、关键修复说明

以下问题在本地部署时已修复，无需额外处理：

### 4.1 Electric 代理参数语法

**问题**：远程服务器用 `params[1]`/`params[2]` 语法向 Electric 传递 WHERE 参数，但 Electric 1.4.13 不支持此语法，导致所有 shape 订阅返回空数据。

**修复**（`crates/remote/src/routes/electric_proxy.rs`）：将参数值直接内联到 WHERE 子句中，替换 `$1`、`$2` 占位符为实际值。

### 4.2 Electric Shape 超时

**问题**：shape 请求从前端直接跨域发到 8080 端口，浏览器流式处理可能失败，3 秒超时后切换到 REST 兜底（30 秒轮询），导致操作卡顿 10+ 秒。

**修复**：
1. Shape URL 改为相对路径（`collections.ts`），走 Vite 代理同源转发
2. 超时从 3 秒增加到 15 秒（兜底保护）
3. Vite 添加 `/v1` 代理转发到远程服务器

### 4.3 Sunset 项目回滚

上游在 `97123d526` 提交中将看板功能替换为"项目已退役"页面。提交 `5ee4367b2` 已完整回滚，恢复看板、Issue、工作区功能。

## 五、常见问题

### 5.1 "Host context is required"

远程 App 直接访问时，仓库操作需要配对本地主机。使用本地 App（`http://localhost:3000`）即可。

### 5.2 Docker 网络问题

- **APT 502**：`deb.debian.org` 被墙，Dockerfile 已用阿里云镜像
- **pnpm ECONNRESET**：`registry.npmjs.org` 被墙，Dockerfile 已用 npmmirror
- **Rust tls handshake eof**：`static.rust-lang.org` 被墙，需通过代理下载

### 5.3 创建 Issue 无响应

检查远程服务器是否正常运行（`curl localhost:8080/v1/health`），以及 Electric 是否健康（`docker ps | grep electric`）。

### 5.4 页面报 401

退出登录后正常现象，重新 GitHub 登录即可。旧 session 在服务器重启后可能失效。
