# Vibe Kanban 部署须知

## 项目架构

项目包含两套前端 + 两套后端：

| 组件 | 说明 | 路径 |
|------|------|------|
| 本地桌面 App | React + Vite，处理本地仓库/工作区 | `packages/local-web/` |
| 远程云端 App | React + Vite，团队协作，内嵌于 Docker | `packages/remote-web/` |
| 本地后端 | Rust Axum，处理本地文件/仓库/工作区 | `crates/server/` |
| 远程后端 | Rust Axum + PostgreSQL + ElectricSQL | `crates/remote/` (Docker) |

核心概念：**远程后端负责登录、项目、Issue；本地 App 负责仓库操作和工作区执行。** 两者配合使用才能获得完整体验。

---

## 一、前置条件

- Node.js 20+、pnpm
- Rust nightly（见 `rust-toolchain.toml`）
- Docker Desktop（仅远程后端需要）
- GitHub OAuth App（或自托管本地账号）

---

## 二、仅启动本地 App（不需要远程后端）

不需要 Docker，可直接启动：

```bash
pnpm i
pnpm run dev
```

前端默认 `http://localhost:3000`。此模式下：
- 无登录功能（`VK_SHARED_API_BASE` 未设置）
- 可直接进入看板使用
- 仓库选择、工作区创建等本地功能正常

## 三、部署远程后端（Docker）

### 3.1 环境变量

在项目根目录创建 `.env.remote`：

```env
# 必填 - JWT 签名密钥
VIBEKANBAN_REMOTE_JWT_SECRET=<openssl rand -base64 48 生成>

# 必填 - ElectricSQL 角色密码
ELECTRIC_ROLE_PASSWORD=<随机密码>

# GitHub OAuth（至少配一种登录方式）
GITHUB_OAUTH_CLIENT_ID=<你的 GitHub OAuth App Client ID>
GITHUB_OAUTH_CLIENT_SECRET=<你的 GitHub OAuth App Client Secret>

# 或者自托管本地账号
SELF_HOST_LOCAL_AUTH_EMAIL=admin@example.com
SELF_HOST_LOCAL_AUTH_PASSWORD=<你的密码>

# 可选
DOMAIN=localhost:8080
```

### 3.2 国内网络适配

如果你在中国大陆，`deb.debian.org`、`registry.npmjs.org`、`static.rust-lang.org` 可能不可达。Dockerfile 已做以下适配：

- **APT** → 阿里云镜像 `mirrors.aliyun.com`
- **npm/pnpm** → npmmirror 镜像 `registry.npmmirror.com`
- **Rust nightly** → 通过 `http_proxy` 走代理下载

如遇网络问题，检查 Clash 代理是否正常运行（不需要 TUN 模式，系统代理即可）。

### 3.3 端口

Docker Compose 默认映射远程后端到 `localhost:3000`，会与 Vite 冲突。启动时指定：

```bash
REMOTE_SERVER_PORTS=127.0.0.1:8080:8081
```

其中 `8080` 是宿主机端口，`8081` 是容器内端口。

### 3.4 启动命令

```bash
cd crates/remote

# 取消代理环境变量（避免 Docker 容器内走 127.0.0.1 代理）
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY

REMOTE_SERVER_PORTS=127.0.0.1:8080:8081 \
PUBLIC_BASE_URL=http://localhost:8080 \
docker compose --env-file .env.remote up --build -d
```

首次构建约需 30-60 分钟（ARM Mac 模拟 x86_64，release 编译）。后续构建会走缓存，快很多。

### 3.5 验证

```bash
curl http://localhost:8080/v1/health
# 应返回 {"status":"ok","version":"..."}
```

### 3.6 停止

```bash
cd crates/remote
docker compose --env-file .env.remote down
```

## 四、本地 App + 远程后端（完整模式）

### 4.1 启动

确保 Docker 远程后端已启动，然后：

```bash
export VK_SHARED_API_BASE=http://localhost:8080
pnpm run dev
```

本地前端在动态端口启动（如 `http://localhost:3003`）。

### 4.2 工作原理

| 功能 | 处理方 |
|------|--------|
| 登录 / OAuth | Docker 远程后端 (8080) |
| 项目管理 / 看板 | Docker 远程后端 (8080) |
| Issue CRUD | Docker 远程后端 (8080) |
| 选择本地仓库路径 | 本地后端 |
| 创建 / 管理工作区 | 本地后端 |
| 代码执行 | 本地后端 |

本地 App 会将 `/api/remote/*` 请求转发到远程后端，本地 API（`/api/repos`、`/api/workspaces` 等）由本地后端处理。

## 五、常见问题

### 5.1 "Host context is required"

远程 App（`http://localhost:8080`）直接访问时，仓库相关操作需要配对本地主机。解决方法：使用本地 App（`http://localhost:3003`）访问。

### 5.2 Docker apt-get 返回 502

`deb.debian.org` 被墙。Dockerfile 已使用阿里云镜像，如需更换：

```dockerfile
# 修改 Dockerfile 中的这行
RUN sed -i 's|http://deb.debian.org/debian|http://mirrors.aliyun.com/debian|g' ...
```

### 5.3 pnpm install 失败 (ECONNRESET)

`registry.npmjs.org` 被墙。Dockerfile 已使用 npmmirror。如需更换：

```dockerfile
ENV npm_config_registry=https://registry.npmmirror.com
```

### 5.4 Rust nightly 下载失败 (tls handshake eof)

`static.rust-lang.org` 被墙。Dockerfile 通过 `host.docker.internal:7897` 代理下载。确保 Clash 代理运行且端口正确。

### 5.5 Docker Compose 版本过老

`docker-compose.yml` 已适配 Docker Compose v2.17+。如果遇到 `Additional property required is not allowed` 错误，说明你的 Docker Compose 版本太老，请升级。

### 5.6 "Project functionality has been retired"

这是上游仓库的 sunset 提交导致。本项目提交 `5ee4367b2` 已回滚此变更，恢复正常看板功能。
